## 0. 结论先行（对接我们的 Understanding）

| 问题 | 结论 |
|------|------|
| 各 API 是否兼容同一检索串？ | **否**。查询语法与过滤字段都不通。 |
| Understanding 应产出什么？ | **源无关** `sub_queries[].text` + `slots/filters`；由 Retrieval **按源翻译**。 |
| 第一版先接谁？ | **Semantic Scholar（主）** 或 **OpenAlex（免 key 友好）** 二选一即可满足「至少一种」；arXiv 官方 API **弱于**「NL 找论文」。 |
| NL 友好度 | S2 ≈ 可吃短英文 query；OpenAlex **更偏关键词/filter**；PubMed 偏生医布尔；Serper 吃 NL 但只解决 arXiv 曝光。 |
| ID | 必须做 **arxiv_id / S2 paperId·corpusId / OpenAlex W-id / DOI / PMID** 映射，评测对齐 `answer_arxiv_id`。 |

## 2. 分源卡片

### 2.1 Semantic Scholar Academic Graph API

| 项 | 内容 |
|----|------|
| **基址** | `https://api.semanticscholar.org/graph/v1` |
| **鉴权** | Header `x-api-key: <S2_API_KEY>`（无 key 也能打，但限流严；建议申请） |
| **主搜索** | `GET /paper/search` |
| **典型参数** | `query`（必填）、`limit`（≤100）、`offset`、`fields`、`year` 或 `publicationDateOrYear`、`venue`、`fieldsOfStudy`、`minCitationCount`、`openAccessPdf`… |
| **返回要点** | `paperId`、可选 `externalIds.ArXiv`、`corpusId`、`title`、`abstract`、`authors`、`year`、`citationCount`、`references`… |
| **查单篇** | `GET /paper/{id}`；id 可为 S2 hash、`DOI:...`、`ArXiv:...` |
| **批量** | `/paper/search/bulk`（token 分页，适合扫库） |
| **SPAR 用法** | `search_paper_via_query_from_semantic`：关键词/短句 + 近 20 年日期窗 + 按引用排序；注释写明 **NL 长句效果一般** |
| **对我们 slots** | `year_*` → `year`/`publicationDateOrYear`；`venue` → `venue`；`topic/method` → 揉进 `query` 字符串 |

示例：

```http
GET /graph/v1/paper/search?query=federated%20domain%20generalization&limit=10&fields=title,abstract,year,externalIds,authors&year=2020-
```

文档：https://api.semanticscholar.org/api-docs/ · Tutorial：https://www.semanticscholar.org/product/api/tutorial

### 2.2 OpenAlex

| 项 | 内容 |
|----|------|
| **基址** | `https://api.openalex.org` |
| **鉴权** | 可不带 key；建议 `mailto=` 礼貌池；有 key 更稳 |
| **主搜索** | `GET /works` |
| **查询形态** | 常用 `filter=` 组合，而非纯 NL。例：`title_and_abstract.search:KEYWORD`、`publication_year:>2020`、`authorships.author.id:...` |
| **排序** | `sort=cited_by_count:desc` 等 |
| **分页** | `page` + `per-page`（或 cursor） |
| **ID** | Work id 形如 `https://openalex.org/Wxxxx`；常从 `open_access.oa_url` 抽 arXiv |
| **摘要** | 常为 `abstract_inverted_index`，需还原成文本 |
| **SPAR 用法** | `search_paper_via_query_from_openalex`：注释写明 **要关键词、不支持好 NL**；filter 近 20 年 + OA |
| **对我们 slots** | `year`→filter；`venue`→`primary_location.source.display_name` 类 filter（需查现行语法）；`text` 应先压成 **短关键词** |

示例：

```http
GET /works?filter=title_and_abstract.search:retrieval%20augmented%20generation,publication_year:>2019&per-page=10
```

文档：https://docs.openalex.org/

### 2.3 PubMed（NCBI Entrez）

| 项 | 内容 |
|----|------|
| **形式** | BioPython `Entrez.esearch` / `efetch`（XML）；非单一 JSON REST 风格（也有 E-utilities HTTP） |
| **查询** | PubMed 布尔式 / 字段标签（`[Title]`、`[Author]` 等） |
| **ID** | PMID；部分可链到 PMC / arXiv |
| **鉴权** | 需设 `Entrez.email`；高频建议 API key |
| **适用** | 生医；AutoScholar（AI 顶会）收益有限 |
| **SPAR** | `search_from_pubmed` + `fetch_pubmed_json` |

对我们：作为 **domain=bio 时的路由源**，v1 可后置。

---

### 2.4 arXiv API

| 项 | 内容 |
|----|------|
| **形式** | 官方 Atom API / Python `arxiv` 包：`Search(query=..., id_list=...)` |
| **强项** | 按 **arxiv_id** 拉题摘极稳；字段标准 |
| **弱项** | 复杂学术 NL / 布尔体验不如 S2；不是赛题「学术 API」的首选唯一解，但是 **ID 落地与补全文元数据** 刚需 |
| **SPAR/PaSa** | `search_paper_from_arxiv_by_arxiv_id`；PaSa 还用 ar5iv HTML 扩章节 |

对我们：Retrieval 命中后 **统一补全**；评测 ID 优先 arxiv。

---

### 2.5 Serper（Google Search API）→ arXiv

| 项 | 内容 |
|----|------|
| **端点** | `POST https://google.serper.dev/search` |
| **鉴权** | Header `X-API-KEY` |
| **形态** | 普通网页搜索；学术用法：`{query} site:arxiv.org`，可选 `before:YYYY-MM-DD` |
| **产出** | organic links → 正则抽 `arxiv_id` → 再调 arXiv/S2 补元数据 |
| **额度** | 免费档有限（SPAR 注释约 2500） |
| **定位** | **召回通道**，不是规范学术元数据 API；赛题「至少一种学术 API」建议另接 S2/OA |

PaSa 主路径几乎靠它；我们可作辅召回，避免唯一依赖。

## 3. 对比总表

| 维度 | Semantic Scholar | OpenAlex | PubMed | arXiv API | Serper→arXiv |
|------|------------------|----------|--------|-----------|--------------|
| 协议 | REST JSON | REST JSON | Entrez/XML | Atom/`arxiv` 包 | REST JSON |
| Key | 建议有 | 可无 | email(+key) | 无 | **必须** |
| NL 短句 | 尚可 | 弱（要关键词） | 弱 | 弱 | 强（网页） |
| year/venue 过滤 | 参数完善 | filter 完善 | 字段语法 | 有限 | 靠 query 拼接 |
| 引文 | 强 | referenced_works | 有限 | 无原生 | 无 |
| 限流 | 有 key 改善 | 礼貌池 | 有 | 有 | 按套餐 |
| 与金标 arxiv_id | externalIds | oa_url 解析 | 常无 | 原生 | 直接抽 id |
| 满足赛题「学术 API」 | ✅ | ✅ | ✅ | 偏预印本库 | ❌偏搜索引擎 |

## 4. 推荐适配层（与 slots 对齐）

```text
SubQuery { text, filters:{year_from, year_to, venue, authors, method} }
        │
        ├─ semantic:  query=text(+method); year=year_from-year_to; venue=venue
        ├─ openalex:  filter=title_and_abstract.search:keywords(text); publication_year:...
        ├─ pubmed:    仅 domain 命中生医时；把 text 收成布尔式
        ├─ arxiv:     主要 id_list 补全；或简单 query
        └─ serper:    f"{text} site:arxiv.org" + before:
```

**ID 归一（评测前）：**

```text
优先 arxiv_id
  else DOI → 反查 S2/OA
  else title 规范化（keep_letters）临时对齐
```

## 5. ScholarIR 落地建议

| 优先级 | 动作 |
|--------|------|
| P0 | 接 **一个**：S2 或 OpenAlex；实现 `retrieve()` 真正返回 `PaperRef` |
| P0 | 消费 Understanding 的 `filters.year_*` |
| P1 | 双源 S2+OA；去重键：arxiv_id > DOI > title_norm |
| P1 | Serper 作可选高召回（控预算） |
| P2 | PubMed 路由；S2 references 做 RefChain |

环境变量（已有示例）：`S2_API_KEY`、`GOOGLE_SERPER_KEY`；OpenAlex 可加 `OPENALEX_MAILTO`。

---

## 6. 和「查询扩展」的关系

- 扩展产出的是 **通用 text**；API 差异在 Retrieval 消化。  
- OpenAlex/S2 对长 NL 都不完美 → Understanding 扩展时应倾向 **短关键词串**（尤其准备打 OA 时），或 Retrieval 内再做「源感知抽词」（SPAR 已有模板）。
