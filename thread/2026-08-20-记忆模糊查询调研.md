# Thread：数据集里有没有「用户记忆模糊」类 Query？要不要做这一层？

> 日期：2026-08-20  
> 数据：PaSa AutoScholarQuery / RealScholarQuery；对照调研中的 SPARBench / PaperFindingBench / LitSearch

---

## 1. 什么叫「记忆模糊」层

典型用户行为：

- 想找**某一篇**论文，但只记得大概内容 / 半截标题 / 「好像 2019 谁谁发的」  
- 口误、错别字、导航式（作者+年份+关键词）  
→ 系统需要 **specific / navigational** 通路（标题匹配、作者检索、模糊消歧），而不是纯主题列表检索。

---

## 2. 本地公开集实测（PaSa）

### RealScholarQuery（50，真实研究者）


| 信号                            | 结果                                                                                                          |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------- |
| 「that paper / titled / 模糊记得」等 | **≈0**                                                                                                      |
| 主导形态                          | 「给我一类论文 / 方法 / 现象」的 **主题检索**                                                                                |
| 金标规模                          | 均约 **15.8** 篇（几乎不是「找一篇」）                                                                                    |
| 少量短查询                         | 如 *「Video aesthetics score…」*、*「Scaling Laws for Fine-Grained MoE」* —— 像关键词/标题碎片，但是 **主题检索句**，不是「我记得有一篇…」叙事 |


**结论：Real 上几乎没有「记忆模糊找单篇」场景。**

### AutoScholarQuery test（1000，Related Work 合成）


| 信号                                 | 约占                                    |
| ---------------------------------- | ------------------------------------- |
| list/papers/studies 等「找一批」         | ~75%                                  |
| 明显「哪篇引入了 XX / the paper that…」等找单篇 | **~1% 量级**                            |
| bib 占位符（`bib.bib31`）               | ~0.3%（合成伪影，开放检索不好用）                   |
| 口语错别字 / forgot / something like    | **基本没有**                              |
| 单篇金标（|answer|=1）                   | ~44% —— 多是「引入某方法的那篇」式 **精确语义**，不是记忆残缺 |


示例（有，但稀）：

- *Which paper introduced the method known as CoT prompting?*  
- *What is the paper that introduced the MGSM dataset?*  
- *What research extended the work of Zaheer et al. …?*

这是 **specific 语义检索**，用户描述往往仍较完整；不是「标题想不起来」的模糊记忆。

## 3. 其他基准（文档口径，非本次全文扫）


| 集                           | 与「模糊记忆」关系                                  |
| --------------------------- | ------------------------------------------ |
| **SPARBench**               | 强调多意图、**口语/错别字**、跨域 → 更接近「脏查询」，但未必是找单篇记忆模糊 |
| **LitSearch**               | 显式 **broad / specific**；specific 偏「找这篇」    |
| **PaperFindingBench（Asta）** | **导航 / 元数据 / 语义** 混合；导航≈书目记忆不全时的找论文        |
| **赛题隐藏集（调研推断）**             | 可能含口语、否定、元数据约束 → **不能假设没有**                |


---



## 4. 要不要做「记忆模糊 / 导航」层？


| 阶段                      | 建议                                                                                               |
| ----------------------- | ------------------------------------------------------------------------------------------------ |
| **现在（主刷 Auto/Real F1）** | **先不做独立重模块**。主路径保持：主题理解 → 改写扩展 → 多源检索 → Judge。                                                   |
| **Understanding 里轻量预留** | 保留 `intent=specific`（已有）；遇到「introduced / the paper that / et al.」可走 **偏精确的改写**，仍共用检索，不必上单独向量标题库。 |
| **有余力 / 对接 Asta 或怕隐藏集** | 再加 **Navigational 旁路**：标题近似匹配、作者+关键词、（可选）拼写纠错。Paper Finder 的 SPECIFIC_BY_TITLE/NAME 可参考。         |


**一句话：**  
当前官方推荐公开集（PaSa）**几乎不逼你做「用户记不清标题」专用层**；有少量 **找单篇/精确语义** 查询，用 `intent=specific` + 精改写即可。口语脏查询、导航找篇主要在 **SPARBench / PaperFindingBench / 隐藏集** 风险里，列为 **P2 泛化**，不是 Understanding v1 的阻塞项。

---



## 5. 和「查询扩展」的关系

- 公开主集更需要的是：**主题改写 / 扩展（抬召回）+ 槽位过滤/Judge（保精度）**。  
- 「记忆模糊」层解决的是另一类失败模式；**数据上不优先于扩展**。
