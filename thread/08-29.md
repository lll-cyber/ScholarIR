## 0. 结论先行

| 议题 | 结论 |
|------|------|
| Understanding 是否可接 Retrieval | **可以**。表示层已基本稳定；继续无限调 synonym prompt 收益低 |
| 当时最该修的 bug | **criteria 不要依赖 intent**；应从 `terms[]` / required 语义单元确定性抽取（P0） |
| coverage_gap 机制 | 已通；但 `intent=specific` 曾挡住 conceptual，需放行（P1） |
| 学术 API 有没有 topic/method 槽 | **没有**。最终只吃 query 字符串 + year/venue 等真 filter |
| role=topic/method 对 API | **几乎无用**；可降级为可选 hint，服务 Filter/改写策略 |
| 堆砌术语 vs 自然语言 | 对 S2 relevance / OpenAlex / arXiv：**短术语串或 skeleton 更好**；完整 NL 通常更差 |
| 子查询是什么 | **检索单位**，不是自然语言问句。Lexical ≈ 换术语；Conceptual ≠ 换术语 |
| 布尔 OR 能否取消子查询 | 仅对**支持布尔的 API**；S2 `/paper/search` 不支持，仍需多路 union ≈ 软 OR |
| query 里除 term 外还有什么 | **claim / conceptual intent（主张/思想层）**；用 coverage_gap → conceptual 召回 |

## 1. 对话起点：6 条 demo 暴露的问题

用户判断（摘要）：

1. 重复 / auto term 基本消失；`coverage_gap → conceptual` 开始工作  
2. 最大问题变为：**LLM 对 intent / semantic constraint 理解不稳定**  
3. 最明显工程 bug：`autoregressive transformer + video` 与 `target network + DQN` 的 `criteria` 只剩 `topic`  
4. 建议：**criteria 从 slots/terms 推导，不由 intent 决定**；Understanding 够用后进 Retrieval A/B，少调 prompt  

助手对齐根因：

- `slots_to_criteria` 只看顶层 `slots.method`，忽略 `terms[].role=method`  
- Filter 硬规则主要看 `slots.topic`，未真正 enforce structured criteria  
- `coverage_gap=true` 时 `intent=specific` 禁止 semantic，改走 `raw`

## 2. `criteria` / `slots_to_criteria` 是什么

### 2.1 字段

正式名：`UnderstandingResult.relevance_criteria`

- **给 Filter / Judge** 用的相关性判定标准  
- **不是**检索用的 `sub_queries`  

| 字段 | 下游 | 作用 |
|------|------|------|
| `sub_queries` | Search | 去 API 搜什么 |
| `relevance_criteria` | Filter/Judge | 搜回来怎么判 relevant |

### 2.2 改前逻辑（有 bug）

```text
永远加 topic（skeleton 或 slots.topic）
若 slots.method 非空 → 加 method
若 negation → 加 negation
追加 intent（weight=0）
```

→ terms 里的 method 进不了 criteria。

### 2.3 改后（P0）

从 **required semantic units** 确定性抽取：

```text
terms[].role + required
  + slots.method
  + skeleton（fallback topic / claim 信号）
  + negation
→ [{type, text, required, description, weight}, ...]
```

Filter：对 required 的 `topic/method/entity/claim` 做硬约束（缺失则 0 分）。

## 4. Understanding 当前总流程

入口：`understand(question, options)` → `UnderstandingResult`

```text
User Query (NL)
    │
    ├─ raw_only? → 单条 SubQuery=原文，结束
    │
    ▼
1. Round1 Extract（LLM / heuristic）
   → intent, terms[], query_skeleton, coverage_gap_likely
    │
    ▼
2. Slot Usage（规则，不调 LLM）
   → api_filters + ExpansionTask（core + 高置信 span swap）
   → gap 时 semantic_reserve；不 pad 到 max_n
    │
    ▼
3. Semantic Reformulation（条件）
   → coverage_gap_likely 时 LLM conceptual（≤2）
   → specific 也允许
    │
    ▼
4. Finalize + Assemble
   → budget；ExpansionTask → SubQuery[]
   → slots_to_criteria → relevance_criteria
    │
    ▼
UnderstandingResult { intent, slots, relevance_criteria, sub_queries, trace }
```

### Intent vs Criteria

```text
intent  → search strategy（survey 修饰、specific 路径等）
terms   → relevance_criteria（不依赖 intent）
```

### Round1 = 一次 LLM 提示

文件：`llm_extract.py`（system + user JSON schema）

要点：intent 路由；terms vs skeleton 两层；高置信 variants；`coverage_gap_likely`；不直接输出最终 sub_queries。

另：gap=true 时还有第二次 LLM（`llm_semantic.py`）做 conceptual。

## 6. 学术 API 能力 vs Schema：是否 over-engineering

### 6.1 API 实际吃什么

| 源 | query | 结构化 filter |
|----|-------|----------------|
| S2 `/paper/search` | 纯文本相关性，**无布尔** | year, venue, … |
| S2 `/paper/search/bulk` | 支持 `+ \| - "phrase` 等 | 批量扫库向 |
| OpenAlex | 偏关键词；可有 AND/OR/NOT 等 | year 等 filter；另有 semantic 模式限流严 |
| arXiv | 弱 NL，术语向 | year 等 |

**没有** `topic=` / `method=` / `task=` 这种语义槽位参数。

我们 adapt 现状：几乎只把 `SubQuery.text` 塞进 query，再附 year/venue。

### 6.2 两个关键问题

**Q1：是否只要抽术语，不必定义 task/topic？**

- 对 **API 调用**：是  
- 对 **Filter / 改写强度**：role 仍有参考价值，但应 **降级为可选 hint**  
- 一等公民应是：`required`、`replaceable`、`variants`、`coverage_gap_likely`、真 filter  

**Q2：堆砌术语是否够，要不要 NL？**

| 模式 | 建议 |
|------|------|
| S2 relevance / OA / arXiv 主路径 | **术语串 / skeleton 短语**，不要完整 NL 问句 |
| 布尔源 | 组内 OR、组间 AND，可少请求 |
| OA semantic 等 | 需自然语言，但限流/上限，仅补充 |

`angle=raw` 完整问句对主路径通常更差。

### 6.3 演进方向（讨论共识，未全部实现）

```text
现在：skeleton + 多 SubQuery（span swap）+ 条件 conceptual
  ↓
目标：
  filters（year/venue/…）
  + term_groups（canonical + variants 一次抽齐）
  + 源感知检索单位：
      布尔源 → 1 条 OR/AND
      非布尔 → 多单位 union（软 OR）
  + gap → conceptual 单位（独立，不进同义词 OR）
  + required texts → Filter
```

**不必删 `sub_queries` 字段**——语义改为「检索单位」即可；布尔源 `len` 小，非布尔源仍是换术语多路。

## 7. 子查询到底是什么

子查询 **≠ 自然语言问句**，而是 **一次 API 调用的检索串**。

| 类型 | 是否「换术语」 | 例子 |
|------|----------------|------|
| core | 规范术语组合 | `autoregressive transformer video generation` |
| lexical variant | 是 | `autoregressive model video synthesis` |
| boolean pack | 换术语但合成 1 条 | `(A\|A') AND (B\|B')` |
| **conceptual** | **否** | `data quality versus quantity in LM pretraining` |
| raw NL | 用户原句 | specific 兜底，少用 |

> Lexical 子查询 ≈ 换术语（或布尔打包）  
> Conceptual 子查询 ≈ 换**学术表述 / 思想说法**，不是同义词表

## 8. Term 之外：Claim / Conceptual Intent

用户指出：除 terms 外，query 里还有如

> smaller dataset better than larger  

可勉强对应 `less is more` 等说法，但本质是 **思想/主张层检索**，说法很多。

### 8.1 命名

| 名称 | 含义 |
|------|------|
| **Claim / Proposition** | 可对错的科学判断（最贴） |
| Relational / comparative intent | 比较、因果、条件 |
| Conceptual expansion | 为召回换学术表述 |
| Vocabulary mismatch | 用户说法 ≠ 论文说法（gap 根因） |

### 8.2 与 term 对比

| | Term | Claim / Idea |
|--|------|--------------|
| 是什么 | 可索引概念节点 | 概念间的关系/判断 |
| 论文出现 | 常直接写 | 常换成另一套说法 |
| 检索 | synonym / abbrev / OR | **conceptual reformulation** |
| 变体 | 近义 | 多种合法解释，非唯一标准词 |

### 8.3 系统对应

- `query_skeleton.core_text` — 保住关系  
- `coverage_gap_likely` — 需要思想层检索  
- `angle=conceptual` — 思想层检索单位  
- criteria `claim` — Filter 侧主张约束  

**不要**把 claim paraphrase 全塞进 term 同义词再用 OR 糊弄；应作为 **独立 conceptual hypotheses**，ranking 降权/分路。

## 9. 建议的后续优先级（对话共识）

1. **少调 Round1 synonym prompt**；用 Retrieval A/B（Recall@K 等）验证  
2. Schema 轻量演进：`term_groups` + 弱化强制 `role`；真 filter 与 required 文本约束为主  
3. 源感知组装：OpenAlex / S2 bulk 可试布尔打包；S2 relevance 保持多路 union  
4. Conceptual 保持独立路径；论文故事线落在 **coverage gap → conceptual expansion**  
5. Ranking 对 `angle=conceptual` 降权，避免 over-specific hypothesis 主导

## 11. 一句话总览

> Understanding 的价值不在「给 API 填 topic/method 槽」，而在：**抽出 required 术语与真 filter、生成更好的检索串（术语/skeleton）、识别 claim 级 vocabulary gap 并触发 conceptual 召回，再用 criteria 在检索后强制约束。**  
> 子查询是检索单位：能布尔则打包，不能则多路换术语；conceptual 始终单独一路。
